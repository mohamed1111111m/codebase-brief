**Browser-based coding chats cannot see your local repo.** Codebase Brief turns one coding task into a short, reviewable file shortlist—with excerpts, reasons, and source paths—so you can give ChatGPT, Claude, or another chat the project context it cannot inspect itself.

It works locally, without an AI service or account. Review the brief, save it, or paste it into ChatGPT, Claude, or another assistant that cannot inspect your local working tree.

**Best fit:** a browser chat that cannot inspect your local files, or a task where you want to choose exactly what context to share. If your coding agent already reads and indexes the working tree, its built-in repo tools may be enough.

## Install the latest build

You need Python 3.10 or newer. Git is optional when running the app, but required to install the latest build from GitHub and to use recent-history or base-diff details.

The current PyPI release is `0.1.0`. The latest GitHub build also includes the reviewed-file feedback summary and importer-aware `--base` selection. To try those changes, install the latest build with `pipx`:

```powershell
pipx install --force git+https://github.com/mohamed1111111m/codebase-brief.git
brief "C:\work\my-app" --task "Trace the login flow" --copy
```

The brief is copied to your clipboard for pasting into your assistant. Replace the example path and task with yours. To use the numbered menu, run `brief` with no arguments.

If you prefer the published PyPI release, install it instead:

```powershell
pipx install codebase-brief
brief
```

Or use a virtual environment for the published release:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade codebase-brief
codebase-brief
```

On macOS or Linux, activate the environment with `source .venv/bin/activate` after creating it with `python3 -m venv .venv`.

If the `brief` command is not available, use `python -m context_inject` while that same virtual environment is active.

## Use the menu

When the menu opens, it uses the folder you launched it from as the starting project. Type a number and press Enter:

1. **Build a context brief** — describe the coding task, optionally enter a Git base ref, then accept or change the approximate size limit.
2. **Choose a different project** — point the tool at another local repository or source folder.
3. **Help and examples** — see the workflow and an example command.
0. **Exit** — close the menu.

In plain terms, Codebase Brief makes a small guide to a project so an AI coding assistant can get oriented before helping with a task. It does not write or fix code. It reads project information locally and prepares a guide for you to review and share.

Before generating the brief, the tool shows suggested files and why they were selected. Press Enter to keep the checked files, type file numbers to toggle selections, or use `add path/to/file.py` to include another safe text file from the repository. Type `none` for an overview without source excerpts. After the brief is shown, saved, or copied, Codebase Brief prints a copyable summary of files kept, removed, added from suggestions, and manually added. To help improve file selection, paste that summary into the [tester feedback form](https://github.com/mohamed1111111m/codebase-brief/issues/new?template=tester-feedback.yml) along with your task and whether the brief helped. Do not include private source code or secrets. The menu's save-here choice writes `context.md` in the folder where you launched the menu; if that is the target repository, the file will be created there. Choose the show or copy option to avoid writing a file into that folder.

For your first try, choose a project you know and a task you understand. Check whether the suggested files are the ones you would have shown a coding assistant yourself.

## Run it with a command

You can skip the menu and generate a brief directly:

```powershell
codebase-brief "C:\work\my-app" --task "Add authentication middleware" --base main --budget 2400 --output context.md
```

Replace the example folder and task with your own. `--base main` prioritizes files changed between `main` and the current `HEAD`; omit it if you do not want a Git diff. `--output context.md` saves the result to that path. Without `--output`, the brief is printed in the terminal.

To copy the result directly to your clipboard, use `--copy` instead of `--output`:

```powershell
codebase-brief "C:\work\my-app" --task "Find the login flow" --copy
```

The generated Markdown is a starting map for your assistant, not a complete copy or analysis of the repository. Review it, then paste the whole brief into the coding assistant where you want to work. It tells the assistant to answer the **Task** at the top using the brief as context. Codebase Brief prepares the handoff; the AI chat does the analysis or coding.

## What it includes

- Project documentation and common stack manifests, such as `package.json` and `pyproject.toml`.
- Recent Git commit subjects and changed paths when Git is available.
- A short list of task-related files with a note explaining each suggestion.
- Small excerpts from selected files, within the requested size budget.
- Source paths throughout the brief so you can open and verify the material.

The file picker uses task words, recent changes, selected Git diffs, common entry points, and direct local Python or JavaScript/TypeScript imports. With `--base`, it also scans supported source files for direct imports of changed files. It understands literal dynamic imports, Python `importlib` calls with literal module names, and simple `paths` aliases in `tsconfig.json` or `jsconfig.json`. This is still static analysis: imports assembled from runtime values, complex config inheritance, generated modules, and unsupported languages may be missed.

## Privacy and limitations

- Repository reading and brief generation happen on your computer. The application has no AI calls, telemetry, or hosted service.
- The tool does not write to the target repository just to read it or generate a brief. It writes a file only when you choose a save option; menu option 2 saves `context.md` in the current working folder, which may be the target repository.
- Common credential files, ignored files, generated files, and private-key files are excluded. Some recognizable secret formats and assignments are redacted.
- Filtering is best-effort, not a security guarantee or full secret scan. Review the brief before sharing it, especially when working with private code.
- The size budget is approximate: it estimates tokens from character count and is not tied to a particular model tokenizer.
- Without Git, the tool still reads supported documentation and manifests, but cannot include Git history or diff details.
